# Programs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A device's `programs:`: named sequences of `turn_on` / `turn_off` / `toggle` / `delay` on its own entities, each a `button` that runs it through HA's `Script` helper.

**Architecture:** `Feature` gains `actions` (services its entities take) and `acts` (what a block acts on). `programs` is a `configured` feature on `Platform.BUTTON` that reuses alerts' `refers` / `follows` for its targets; `_device` checks each target's feature takes the action. Each `Program` button holds an HA `Script` built from the translated steps, started in the background on press, unloaded when the entity is removed.

**Tech Stack:** Python 3.14, Home Assistant 2026.9.3 (`homeassistant.helpers.script.Script`, `ButtonEntity`), voluptuous, pytest with `pytest-homeassistant-custom-component`, docs.page MDX.

**Spec:** `docs/superpowers/specs/2026-09-27-programs-design.md`

## Global Constraints

- Branch is stacked on `feat/alerts`: `Feature.refers`, `PururuEntity.follows`, `_referable` and the `watches`/`follows` errors come from there. Don't reimplement them.
- Entity ID: `button.pururu_<device key>_program_<program key>`; namespace `program`; feature key `programs`.
- A step is a mapping with exactly one key: `delay`, `turn_on`, `turn_off` or `toggle`. Targets are qualified entity keys as in an entity ID (`switch_pump`), `cv.slug`.
- Program `name`: required, `vol.All(cv.string, vol.Strip, vol.Length(min=1))`, not translated. `sequence`: required, at least one step.
- New config error: `programs: <key> does not take <action>`. Existing refers error, reused: `programs: <key> is not an entity key of another feature of this device`.
- `script_mode="single"`; a press while running logs `<Device name> <program name>: Already running` (HA's own warning).
- Press returns at once; a reload/unload stops a running program (`Script.async_unload`); what it did stays.
- Version: `custom_components/pururu/manifest.json` → `0.1.7` (alerts is `0.1.6`); `python3 release.py check` must pass. Re-check at merge time if `lights` merged first.
- Run everything with `uv run` from the worktree root. Tests: `uv run pytest tests/<file> -n 0 -q`. Full gate: `uv run pytest` (includes ruff, ruff format, mypy strict, hassfest).
- Never leave the shell's cwd inside `.venv/.../homeassistant/helpers/`.
- Docs: MDX — keep `{` and `<` in backticks or code blocks. `pnpm docs:check` must pass. Use pnpm, never npm.

## Review Focus

1. **A press while the target switch is `unavailable`** (the real switch gone): the program must go on (HA skips unavailable entities) and still turn it off later, not crash or stop. → Task 2, `test_an_unavailable_switch_does_not_stop_it`.
2. **A step that raises** (the real switch's service fails): the program stops, the error is logged with the program's name, the press itself doesn't fail. → Task 2, `test_a_failing_step_stops_it_and_is_logged`.
3. **Reload during a `delay`**: the old `Script` must not live on and turn the pump off two hours later behind the new entry's back. → Task 3, `test_a_reload_stops_a_running_program`.
4. **A program that `_creatable` drops** (its target's ID taken): no `Script` may be left registered in `hass.data` for an entity never added. → Task 3, `Script` built in `async_added_to_hass` + `test_a_program_whose_target_is_not_created_is_not_created`.
5. **The same target twice, and `toggle`**: `turn_on` then `turn_off` of one key, and `toggle` flipping it, both reach the real switch in order. → Task 2, `test_pressing_runs_the_sequence` and `test_toggle_flips_the_switch`.

```python
"""Programs: sequences of actions on the device's own entities, each run by a button.

A program is a method of its device: someone presses it, and it turns the
device's own switches on and off, with delays between. Its steps are pururu's,
translated to Home Assistant's script syntax and run by HA's Script helper; no
step can reach outside the device.
"""

from collections.abc import Iterator, Mapping
import logging
from typing import Any, override

import voluptuous as vol

from homeassistant.components.button import ButtonEntity
from homeassistant.const import Platform
from homeassistant.core import HomeAssistant, split_entity_id
from homeassistant.helpers import config_validation as cv
from homeassistant.helpers.script import SCRIPT_MODE_SINGLE, Script

from ..const import DOMAIN
from ..entity import PururuEntity
from ..feature import Device, Feature

_LOGGER = logging.getLogger(__name__)

DELAY = "delay"
# What a step can do to an entity; `_device` checks the entity's feature takes it.
# Fixed here: this module can't read FEATURES, which imports it
ACTIONS = ("turn_on", "turn_off", "toggle")

STEP = vol.Schema(
    {
        vol.Optional(DELAY): cv.positive_time_period,
        **{vol.Optional(action): cv.slug for action in ACTIONS},
    }
)


def _step(value: Any) -> dict[str, Any]:
    """One of delay, turn_on, turn_off, toggle, with its value: exactly one key."""
    step: dict[str, Any] = STEP(value)
    if len(step) != 1:
        raise vol.Invalid(f"a step is exactly one of {DELAY}, {', '.join(ACTIONS)}")
    return step


PROGRAM = vol.Schema(
    {
        # A blank name would show the program as its device's name alone
        vol.Required("name"): vol.All(cv.string, vol.Strip, vol.Length(min=1)),
        vol.Required("sequence"): vol.All([_step], vol.Length(min=1)),
    }
)
# A schema of its own: ALLOW_EXTRA would let a key that isn't a slug through
SCHEMA = vol.All(vol.Schema({cv.slug: PROGRAM}), vol.Length(min=1))


def _targets(program: dict[str, Any]) -> Iterator[tuple[str, str]]:
    """(action, entity key) of each step that acts on an entity, in order."""
    for step in program["sequence"]:
        yield from ((action, key) for action, key in step.items() if action != DELAY)


def _acts(config: dict[str, Any]) -> list[tuple[str, str]]:
    return [pair for program in config.values() for pair in _targets(program)]


def _refers(config: dict[str, Any]) -> set[str]:
    return {key for _, key in _acts(config)}


def _translated(
    program: dict[str, Any], inputs: Mapping[str, str]
) -> list[dict[str, Any]]:
    """The steps in Home Assistant's script syntax, on the targets' current entity IDs."""
    sequence: list[dict[str, Any]] = []
    for step in program["sequence"]:
        ((action, value),) = step.items()
        if action == DELAY:
            sequence.append({DELAY: value})
            continue
        entity_id = inputs[value]
        sequence.append(
            {
                "action": f"{split_entity_id(entity_id)[0]}.{action}",
                "target": {"entity_id": entity_id},
            }
        )
    validated: list[dict[str, Any]] = cv.SCRIPT_SCHEMA(sequence)
    return validated


class Program(PururuEntity, ButtonEntity):
    """Pressed, it starts its sequence and returns; a press while it runs is ignored."""

    def __init__(
        self,
        device: Device,
        entity_key: str,
        name: str,
        sequence: list[dict[str, Any]],
        follows: tuple[str, ...],
    ) -> None:
        """Run `sequence` as `entity_key` of `device`, named `name`, acting on `follows`."""
        self._identify(device, Platform.BUTTON, entity_key, name)
        self.follows = follows
        self._title = f"{device.name} {name}"
        self._sequence = sequence
        # Built once added: an entity that is never added leaves no script behind
        self._script: Script | None = None

    @override
    async def async_added_to_hass(self) -> None:
        await super().async_added_to_hass()
        self._script = Script(
            self.hass,
            self._sequence,
            self._title,
            DOMAIN,
            logger=_LOGGER,
            script_mode=SCRIPT_MODE_SINGLE,
        )

    @override
    async def async_press(self) -> None:
        """Start the sequence without waiting for it, as script.turn_on."""
        if self._script is None:
            return
        self.hass.async_create_background_task(
            self._script.async_run(context=self._context),
            f"{DOMAIN} program {self.entity_id}",
        )


def build(
    hass: HomeAssistant,
    device: Device,
    config: dict[str, Any],
    inputs: Mapping[str, str],
) -> list[PururuEntity]:
    """A button per program, on the current entity IDs of what it acts on."""
    return [
        Program(
            device,
            entity_key,
            program["name"],
            _translated(program, inputs),
            tuple(dict.fromkeys(key for _, key in _targets(program))),
        )
        for entity_key, program in config.items()
    ]


PROGRAMS = Feature(
    schema=SCHEMA,
    entity_keys={},
    build=build,
    example={
        "clean": {
            "name": "Clean",
            "sequence": [
                {"turn_on": "switch_pump"},
                {"delay": {"hours": 2}},
                {"turn_off": "switch_pump"},
            ],
        }
    },
    namespace="program",
    configured=Platform.BUTTON,
    refers=_refers,
    acts=_acts,
)
```

`programs` gives a device things it knows how to do, such as a pool's cleaning: turn the pump on, wait two hours, turn it off. Each program becomes a button of the device. Pressing it runs the program's steps, on that device's own entities only.

```yaml
pururu:
  devices:
    pool:
      name: Piscina
      switches:
        pump: {entity: switch.pool_pump, name: Bomba}
      programs:
        clean:
          name: Limpar
          sequence:
            - turn_on: switch_pump
            - delay: {hours: 2}
            - turn_off: switch_pump
```

This creates `button.pururu_pool_program_clean`, shown as **Piscina Limpar**.

## Settings

`programs` is a map of **program key → program**, with at least one program. The key is a slug, and it ends the entity ID after the namespace `program`: `clean` → `button.pururu_pool_program_clean`.

<Property name="name" type="string" required>
  The name shown after the device's name. It can't be empty, and it's the same in every language.
</Property>

---

<Property name="sequence" type="list of steps" required>
  The steps, run in order. At least one.
</Property>

## Steps

Each step has exactly one key:

| Step | What it does |
|---|---|
| `turn_on: <entity key>` | Turns that entity of the device on |
| `turn_off: <entity key>` | Turns it off |
| `toggle: <entity key>` | Turns it on if it's off, off if it's on |
| `delay: <time period>` | Waits, such as `{hours: 2}`, `"00:30:00"` or `90` (seconds) |

An entity key names an entity of **this device**, written as its entity ID ends after the device key: `switch_pump` for `switch.pururu_pool_switch_pump`. It must be an entity of another feature of the device that takes the action. Today that's a [switch](/features/switches). The same entity can appear in several steps.

Anything else is a configuration error: an entity ID (`switch.pool_pump`), another program, a sensor (`turn_on: appliance_power` gives `programs: appliance_power does not take turn_on`), or a Home Assistant action such as `action: switch.turn_on`.

## Only its own device

A program is a method of its device, not a script. It acts only on its device's entities, and it never starts by itself:

- **No other device, no real entity.** To act on a real switch, add it to the device under [`switches`](/features/switches).
- **No templates, no events, no other actions.** Its steps are the four above.
- **No triggers.** Something outside presses it: you, an automation, a voice assistant.

## Entity

`button.pururu_<key>_program_<program key>`. Its state is the time of its last press.

- **Pressing it** starts the program and returns at once: an automation pressing it doesn't wait for it to end. The logbook names who pressed it next to what the program did.
- **Pressed while it runs**, it's ignored, and the log says `Piscina Limpar: Already running`.
- **A step that fails**, such as a real switch reporting an error, stops the program, and the log says why. A switch that's `unavailable` doesn't stop it: that step does nothing and the program goes on.
- **A reload** of pururu stops a running program. What it already did stays: if the pump was on, it stays on. Renaming any pururu entity in the UI reloads pururu too.
- **A restart** of Home Assistant loses a running program, as it does Home Assistant's scripts. The button comes back with the time of its last press.
- If an entity it acts on isn't created, the program isn't either, and the log says so. See [Troubleshooting](/reference/troubleshooting#-follows--which-is-not-created-not-creating-it).

## Good to know

- **Renaming an entity it acts on** in the UI is followed: the program acts on the new ID.
- **Seeing what's running and stopping a program** aren't there yet.
