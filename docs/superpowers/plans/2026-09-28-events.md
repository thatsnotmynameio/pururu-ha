# pururu's events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When `pururu: events:` enables a class, every state change of an entity the entry created is fired on HA's bus as `pururu_state_changed` or `pururu_reading`, with the change and a snapshot of its device, so a user's automation can post it to a webhook.

**Architecture:** A new module `events.py` holds the schema, the two classes and `async_setup`, which tracks the entry's created entities with `async_track_state_change_event`, drops what isn't a real change, classes the change by the new state's `state_class` attribute and fires the event with the state's context. `__init__.async_setup_entry` records which device created each entity and calls `events.async_setup` right after the platforms are set up (when each entity has its current, possibly renamed, ID). pururu speaks no HTTP.

**Tech Stack:** Home Assistant 2026.9 custom integration, voluptuous, pytest-homeassistant-custom-component, `uv`.

**Spec:** `docs/superpowers/specs/2026-09-28-events-design.md`

## Global Constraints

- Version `0.1.19` in `custom_components/pururu/manifest.json`.
- Configuration: `pururu: events:`, a list of `state_changed` and `reading`, each at most once; default `[]` (nothing fired, nothing listens).
- Event types: `pururu_state_changed` (new state has no `state_class` attribute) and `pururu_reading` (it has one).
- Event data keys, exactly: `event_id` (ULID, `homeassistant.util.ulid.ulid_now()`), `event_name` (`<device>.<key>`), `event_class` (`state_changed` | `reading`), `entity_id`, `device`, `device_name`, `key`, `old`, `new`, `time` (new state's `last_changed.isoformat()`), `attributes` (`dict` of the new state's), `states` (`{key: state}` of every created entity of the device that has a state).
- `key` is the entity's unique ID after `pururu_<device>_` (`appliance_last_cycle_end`).
- Not fired: old or new state `None`; old or new state with `restored: true`; same state string.
- Fired with `context=new_state.context`.
- `events` alone doesn't create the entry.
- Lint/type scope: `custom_components/pururu` only (ruff, ruff format, mypy strict). Tests aren't linted.

## Review Focus

- A reload (and the UI rename that triggers one) must be silent: HA writes the `restored` placeholder when unloading and the real state when loading. Task 1, `test_a_reload_is_silent`, `test_a_rename_is_followed`.
- A device key that is a prefix of another (`greenhouse`, `greenhouse_sprinkler`): `key` must come from the device that built the entity, never from parsing the entity ID. Task 1, `test_devices_sharing_a_prefix`.
- An entity renamed in the UI: `entity_id` is the new one, `key` and `event_name` unchanged. Task 1, `test_a_rename_is_followed`.
- A cycle's end: the snapshot must already hold that cycle's duration and energy (`last_cycle_end` is written last). Task 1, `test_a_cycle_end_carries_the_cycle`.
- An entity ID held by another integration is not pururu's and is never fired. Task 1, `test_an_entity_not_created_is_not_fired`.

```python
"""pururu's events: each state change of an entity the entry created, fired on HA's bus.

pururu speaks no HTTP: whatever consumes HA's events takes them from there (for
a webhook, a rest_command in the user's automation). Two classes, each enabled
on its own in `events`: the change of an entity with a state_class is a reading
(a series: power, totals, meters), any other a change (a fact: running, a mode,
the last cycle's end). Each event carries its device's states when it is fired:
a cycle's end (last_cycle_end, written last) comes with that cycle's values.
"""

from collections.abc import Collection, Mapping
from dataclasses import dataclass
from typing import Any, Final

import voluptuous as vol

from homeassistant.components.sensor.const import ATTR_STATE_CLASS
from homeassistant.config_entries import ConfigEntry
from homeassistant.const import ATTR_RESTORED
from homeassistant.core import (
    Event,
    EventStateChangedData,
    HomeAssistant,
    State,
    callback,
)
from homeassistant.helpers import config_validation as cv
from homeassistant.helpers.event import async_track_state_change_event
from homeassistant.util.ulid import ulid_now

from .const import DOMAIN

CONF_EVENTS: Final = "events"
STATE_CHANGED: Final = "state_changed"
READING: Final = "reading"
CLASSES: Final = (STATE_CHANGED, READING)


def event_type(event_class: str) -> str:
    """The type a class's events have on HA's bus: pururu_state_changed, pururu_reading."""
    return f"{DOMAIN}_{event_class}"


def _distinct(classes: list[str]) -> list[str]:
    if len(set(classes)) != len(classes):
        raise vol.Invalid(f"a class is repeated: {classes}")
    return classes


# The classes fired, each at most once; none by default
SCHEMA = vol.All(cv.ensure_list, [vol.In(CLASSES)], _distinct)


@dataclass(frozen=True, kw_only=True)
class Watched:
    """A device whose entities' changes are fired: its key, its name, its created entities (entity ID → key)."""

    key: str
    name: str
    entities: Mapping[str, str]


@callback
def async_setup(
    hass: HomeAssistant,
    entry: ConfigEntry,
    classes: Collection[str],
    devices: Collection[Watched],
) -> None:
    """Fire the enabled classes' events for the devices' entities, until the entry unloads."""
    if not classes:
        return
    owners = {entity_id: device for device in devices for entity_id in device.entities}

    @callback
    def changed(event: Event[EventStateChangedData]) -> None:
        """Fire a real change of its class, if enabled.

        No change: an entity appearing or going (None), HA's restored
        placeholder either way (written when an entity unloads, as at a reload,
        and shown at start-up until it loads), attributes alone.
        """
        old, new = event.data["old_state"], event.data["new_state"]
        if old is None or new is None or old.state == new.state:
            return
        if old.attributes.get(ATTR_RESTORED) or new.attributes.get(ATTR_RESTORED):
            return
        event_class = (
            READING if new.attributes.get(ATTR_STATE_CLASS) is not None else STATE_CHANGED
        )
        if event_class not in classes:
            return
        hass.bus.async_fire(
            event_type(event_class),
            _data(hass, owners[new.entity_id], event_class, old, new),
            context=new.context,
        )

    entry.async_on_unload(async_track_state_change_event(hass, list(owners), changed))


def _data(
    hass: HomeAssistant, device: Watched, event_class: str, old: State, new: State
) -> dict[str, Any]:
    """The event's data: the change, and every state of its device now."""
    key = device.entities[new.entity_id]
    return {
        "event_id": ulid_now(),
        "event_name": f"{device.key}.{key}",
        "event_class": event_class,
        "entity_id": new.entity_id,
        "device": device.key,
        "device_name": device.name,
        "key": key,
        "old": old.state,
        "new": new.state,
        "time": new.last_changed.isoformat(),
        "attributes": dict(new.attributes),
        "states": {
            entity_key: state.state
            for entity_id, entity_key in device.entities.items()
            if (state := hass.states.get(entity_id)) is not None
        },
    }
```

def _event_devices(
    devices: dict[str, dict[str, Any]], created_by: Mapping[str, list[Entity]]
) -> list[events.Watched]:
    """Each device with its created entities: current entity ID → key, its unique ID after pururu_<device>_."""
    return [
        events.Watched(
            key=key,
            name=devices[key][CONF_NAME],
            entities={
                entity.entity_id: str(entity.unique_id).removeprefix(
                    f"{ENTITY_PREFIX}_{key}_"
                )
                for entity in created
            },
        )
        for key, created in created_by.items()
    ]

title: Events
description: pururu fires an event on Home Assistant's bus for every change of its entities, so an automation can send it anywhere, such as a webhook.

Everything pururu knows ends up in the state of one of its entities: a cycle's end is `last_cycle_end`, who opened a door is `last_opened_by`, an alert is its binary sensor. With `events`, pururu also **fires an event on Home Assistant's bus** each time one of those states changes, with the change and a snapshot of the whole device. pururu sends nothing over the network itself: an automation of yours takes the event from the bus and posts it, for example to a webhook.

```yaml title="configuration.yaml"
pururu:
  events: [state_changed, reading]
  devices:
    clothes_washer:
      name: Tanquinho
      appliance:
        power: sensor.washer_plug_power
        energy: sensor.washer_plug_energy
        running: {threshold: 4, on_delay: {minutes: 1}, off_delay: {minutes: 2}}
```

## Two classes

| Class | Event type | Which changes |
|---|---|---|
| `state_changed` | `pururu_state_changed` | Entities **without** a `state_class`: facts such as `running`, a mode, an alert, a door, `last_opened_by`, the last cycle's values, switches, lights. |
| `reading` | `pururu_reading` | Entities **with** a `state_class`: series such as the power and energy mirrors, phases, totals and per-period meters. They can change every few seconds. |

`events` lists the classes to fire, each once. Leave it out (the default) and pururu fires nothing. A class you don't list is never fired. **Developer tools → YAML → Pururu** applies a change.

A change is fired when the state itself changes. pururu doesn't fire:

- an entity appearing or going, as at every reload;
- Home Assistant's placeholder (`unavailable` with `restored: true`), written while an entity unloads or hasn't loaded yet;
- a change of attributes alone.

`unavailable` and `unknown` are fired: they are real states. An entity pururu didn't create, because another integration holds its ID, isn't pururu's and is never fired.

## The data

```json
{
  "event_id": "01J8Z3K4QW6N5V2XK0M7T9R8YB",
  "event_name": "clothes_washer.appliance_last_cycle_end",
  "event_class": "state_changed",
  "entity_id": "sensor.pururu_clothes_washer_appliance_last_cycle_end",
  "device": "clothes_washer",
  "device_name": "Tanquinho",
  "key": "appliance_last_cycle_end",
  "old": "2026-09-27T20:10:00+00:00",
  "new": "2026-09-28T09:52:00+00:00",
  "time": "2026-09-28T09:52:00.123456+00:00",
  "attributes": {"device_class": "timestamp", "friendly_name": "Tanquinho Fim do último ciclo"},
  "states": {
    "appliance_running": "off",
    "appliance_last_cycle_start": "2026-09-28T09:00:00+00:00",
    "appliance_last_cycle_duration": "52.0",
    "appliance_last_cycle_energy": "0.42",
    "appliance_last_cycle_end": "2026-09-28T09:52:00+00:00",
    "appliance_cycles_total": "12"
  }
}
```

| Field | What |
|---|---|
| `event_id` | A new ID per event (a ULID: unique, sorted by time). Use it to drop duplicates. |
| `event_name` | `<device>.<key>`. It doesn't change when you rename the entity in the UI. |
| `event_class` | `state_changed` or `reading`, since a webhook gets the data without the event type. |
| `entity_id` | The entity's current ID. |
| `device`, `device_name` | The device's key and its `name`. |
| `key` | The entity key, as it ends the entity ID: `appliance_running`, `mode_warming_cycles_total`. |
| `old`, `new` | The states, as Home Assistant's text. |
| `time` | When the state changed. |
| `attributes` | The new state's attributes. |
| `states` | Every entity of the device, by `key`, when the event was fired. |

A finished cycle comes in one event: `last_cycle_end` is written last, so when it changes, `states` already holds that cycle's start, duration, energy and count.

## Sending them to a webhook

A `rest_command` posts the data, and an automation calls it for each event:

```yaml title="configuration.yaml"
rest_command:
  webhook_pururu:
    url: !secret webhook_pururu_url
    method: post
    headers:
      X-Webhook-Token: !secret webhook_pururu_token
    content_type: application/json
    payload: "{{ event | tojson }}"

automation:
  - alias: pururu → webhook
    mode: queued        # one at a time, in order
    max: 1000
    triggers:
      - trigger: event
        event_type: [pururu_state_changed, pururu_reading]
    actions:
      - action: rest_command.webhook_pururu
        data:
          event: "{{ trigger.event.data }}"
```

To send only some events, add a condition to the automation, such as `{{ trigger.event.data.device == 'clothes_washer' }}`. To send each class to its own webhook, write two automations.

The receiving side takes them as `POST` requests, checks the `X-Webhook-Token` header against the same token, and can route them on `event_class` or `event_name`. For a finished cycle, match `event_name` ending in `.appliance_last_cycle_end` and read the values from `states`.

## The recorder

Home Assistant's recorder saves every event on the bus, and readings can change every few seconds. Their values are already saved as the entities' states, so leave the events out of the database:

```yaml title="configuration.yaml"
recorder:
  exclude:
    event_types:
      - pururu_reading
      - pururu_state_changed
```

The automation still gets them: the recorder's `exclude` only stops them being saved.
