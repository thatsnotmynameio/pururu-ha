```yaml title="configuration.yaml"
pururu:
  config:
    notify: homeassistant.notify.mobile_app_phone     # where every message goes
    events: [state_changed, reading]    # see events
    alerts:
      lights:
        groups:
          default: [device.biblioteca.lights.teto]
  floors:
    terreo:
      name: Térreo
      level: 0
      icon: mdi:home-floor-0
      aliases: [embaixo]
  areas:
    despensa:
      name: Despensa
      floor: terreo
      icon: mdi:washing-machine
  devices:
    clothes_washer:
      name: Tanquinho
      area: despensa
      appliance:
        power: homeassistant.sensor.washer_plug_power
        energy: homeassistant.sensor.washer_plug_energy
        running_program:
          above: 4
          on_delay: {minutes: 1}
          off_delay: {minutes: 2}
          statistics:
            runtime: [today, week, month, year]
            cycles: [today, week, month, year]
          phases:
            warming: {name: Aquecendo, above: 1000}
            wringing: {name: Centrifugando, above: 50, below: 1000, on_delay: {minutes: 3}}
        programs:
          detected:
            cotton: {name: Algodão, above: 1500, on_delay: {minutes: 5}}
        alerts:
          offline:
        notifications:
          finished:
      alerts:
        long_cycle:
          name: Ciclo longo
          when: appliance.running_program
          state: "on"
          for: {hours: 3}
          priority: medium
          lights: default
          message: A máquina passou de 3 horas ligada!
          done_message: A máquina terminou.
    greenhouse:
      name: Estufa
      switches:
        sprinkler: {entity: homeassistant.switch.greenhouse_sprinkler, name: Irrigador}
      programs:
        executable:
          clean:
            name: Limpar
            sequence:
              - turn_on: switches.sprinkler
              - delay: {hours: 2}
              - turn_off: switches.sprinkler
            statistics: {runtime: [month], cycles: [month]}
      reactions:
        morning: {name: Manhã, at: "08:00", then: clean, statistics: {triggered: [month]}}
      goals:
        watering: {name: Rega, target: 6, period: week, tracked_by: programs.executable.clean.runtime_total}
    biblioteca:
      name: Biblioteca
      lights:
        teto: {entity: homeassistant.light.biblioteca_teto, name: Teto}
        abajur: {entity: homeassistant.switch.sonoff_abajur, name: Abajur}
      reactions:
        washer_done: {name: Lavadora terminou, when: device.clothes_washer.appliance.running_program, from: "on", to: "off"}
        pantry: {name: Despensa abriu, when: homeassistant.binary_sensor.porta_despensa, to: "on"}
        cleaned: {name: Estufa limpa, when: device.greenhouse.programs.executable.clean, from: "on", to: "off"}
        night: {name: Noite, at: "22:00", message: Hora de apagar as luzes.}

automation pururu: !include_dir_merge_list pururu/automations
script pururu: !include_dir_merge_named pururu/scripts

alert2:                          # alerts with texts: see alerts
  alerts: !include_dir_merge_list pururu/alert2
```

## General rules

- `pururu:` has four optional keys: `config`, `floors`, `areas` and `devices`. Any other key is an error.
- Every **key** you choose, whether of a floor, an area, a device, a phase, a switch, a light, an alert, a goal or a detected or executable program, is a **slug**: lowercase letters, digits and `_`.
- A feature's own `alerts` enables its ready-made alerts, one key each: see [Ready-made alerts](/concepts/alerts#ready-made-alerts). The device's `alerts` is for alerts you write.
- A feature's own `notifications` enables its ready-made notifications the same way: see [Notifications](/concepts/notifications#ready-made-notifications).
- A `statistics` counts one of the block's totals per period: in a feature's own block (`appliance`, `door`, `window`), in an appliance's `running_program`, in each of its phases and `other`, in each detected program (and its phases and `other`), or inside each executable program, reaction or button. See [Statistics](/concepts/statistics).
- A reference names an entity by its path in the YAML, from the block it's in, every level written: `appliance.running_program`, `switches.sprinkler`, `appliance.running_program.statistics.cycles.month`. Another device's starts with `device.` and its key (`device.clothes_washer.appliance.running_program`: a reaction's `when`, a light group's member), and anything Home Assistant owns with `homeassistant.` (`homeassistant.sensor.washer_plug_power`, `homeassistant.notify.mobile_app_phone`), in every field that names it. See [References](/concepts/entity-ids#references).
- An alert's `when` names an entity of another block of the same device by its path (`appliance.running_program`, `switches.sprinkler`). See [alerts](/concepts/alerts#settings).
- An executable program's steps name entities of other features of the same device the same way, and each one's feature must take the step's action. See [programs](/concepts/programs#steps).
- A reaction's `when` names an entity of its device, of another device, or of Home Assistant's, or an executable program running (`programs.executable.clean`). See [reactions](/concepts/reactions#an-entity).
- A goal's `tracked_by` names a total of its device, of another device, or Home Assistant's entity that accumulates (`appliance.running_program.runtime_total`, `device.clothes_washer.appliance.running_program.runtime_total`, `homeassistant.sensor.pool_heater_energy`). See [goals](/concepts/goals#settings).
- A field that names one kind of thing takes its key alone: a device's `area`, an area's `floor`, a reaction's `then`, a button's `program`, an alert's `lights` (`then: clean`, not `programs.executable.clean`).
- No two devices give an entity the same ID. Device `greenhouse` with the switch `switch_sprinkler` and device `greenhouse_switch` with the switch `sprinkler` would both have `switch.pururu_greenhouse_switch_switch_sprinkler`, so that's a configuration error. It counts every entity key a feature can create, even one its settings don't: device `greenhouse` with the switch `appliance_energy_total` is refused next to a device `greenhouse_switch` with `appliance`, even without `energy:`, so turning a setting on later never breaks the configuration.
- In one device, a real entity is in one of `switches` and `lights` at most: `switches: homeassistant.switch.sonoff_abajur is already in lights`. Two devices can each use it their own way.
- An unknown key anywhere is a configuration error. When the configuration is invalid, Home Assistant logs why, and a reload **changes nothing**.
- The blocks can be split across [packages](/getting-started/install#packages).

## config

Settings of the whole house, not of a device.

<Property name="notify" type="notify action or list" optional>
  Where every message goes, a reaction's or a ready-made notification's, unless its own `notify` says: `homeassistant.notify.mobile_app_phone`, or a list of them. See [Notifications](/concepts/notifications#where-a-message-goes).
</Property>

---

<Property name="events" type="list" optional>
  The classes of [events](/concepts/events) pururu fires on Home Assistant's bus: `state_changed`, `reading`, each once. None by default.
</Property>

---

<Property name="alerts.lights" type="map" optional>
  The alert lights: `groups` of lights that alerts borrow with `lights`, and what a light shows for each priority (`high`, `medium`, `low`) and once its alerts ended (`resolved`). See [Alert lights](/concepts/alert-lights#settings).
</Property>

## floors

A map of **floor ID → floor**. See [Floors and areas](/concepts/floors-and-areas).

<Property name="name" type="string" required>
  The name Home Assistant shows. It can't be empty.
</Property>

---

<Property name="level" type="integer" optional>
  The floor's level: `0` for the ground floor, negative below it and positive above it. Leaving it out clears it.
</Property>

---

<Property name="icon" type="icon" optional>
  An icon such as `mdi:home-floor-0`. Leaving it out clears it.
</Property>

---

<Property name="aliases" type="list of strings" optional>
  Other names for the floor, for example for voice assistants. A single string is allowed too.
</Property>

## areas

A map of **area ID → area**. See [Floors and areas](/concepts/floors-and-areas).

<Property name="name" type="string" required>
  The name Home Assistant shows. It can't be empty.
</Property>

---

<Property name="floor" type="floor ID" optional>
  The area's floor. It must be a key of `floors:`. Without it, the area is on no floor.
</Property>

---

<Property name="icon" type="icon" optional>
  An icon such as `mdi:palette`. Leaving it out clears it.
</Property>

---

<Property name="aliases" type="list of strings" optional>
  Other names for the area. A single string is allowed too.
</Property>

## devices

A map of **device key → device**. See [Devices and features](/concepts/devices-and-features).

<Property name="name" type="string" required>
  The device's name. It can't be empty.
</Property>

---

<Property name="area" type="area ID" optional>
  The area the device goes in. It must be a key of `areas:`. See [A device in an area](/concepts/floors-and-areas#a-device-in-an-area).
</Property>

---

<Property name="reactions" type="map" optional>
  A map of **reaction key → reaction**, each one a Home Assistant automation. It isn't a feature. A reaction's `then` names one of the device's executable programs (`programs: executable:`), started when it fires, its `message` is told to its `notify` or `config.notify`, and a reaction on `at` or `sun` can `retry`. See [Reactions](/concepts/reactions#settings).
</Property>

---

<Property name="programs" type="map" optional>
  `executable:`, a map of **program key → program**, each one a Home Assistant script. It isn't a feature. See [Programs](/concepts/programs#settings). A detected program sits in its feature's block instead (`programs: detected:`): see [More detected programs](/concepts/programs#more-detected-programs).
</Property>

---

<Property name="alerts" type="map" optional>
  A map of **alert key → alert**, each one a binary sensor on while its condition holds. It isn't a feature. See [Alerts](/concepts/alerts#settings).
</Property>

---

<Property name="goals" type="map" optional>
  A map of **goal key → goal**, each one a `name`, a `target` (a number above 0, in the unit of what tracks it), a `period` (`today`, `week`, `month` or `year`) and `tracked_by`, what accumulates as the work is done: a total of this device or another, or Home Assistant's entity. Each goal is two sensors, its `target` and what was `done` in the period. It isn't a feature. See [Goals](/concepts/goals#settings).
</Property>

---

<Property name="<feature>" type="map" required>
  At least one feature, under its own key:

  - [`appliance`](/features/appliance#settings): an appliance on a power-measuring plug, its `running_program` and phases, and its detected programs (`programs: detected:`).
  - [`door`](/features/door#settings): a door from its contact sensor.
  - [`window`](/features/window): a window from its contact sensor.
  - [`lights`](/features/lights#settings): real lights, or relays that drive a lamp, inside the device.
  - [`switches`](/features/switches#settings): real switches inside the device.
  - [`buttons`](/features/buttons#settings): a value of a real sensor, such as a remote's key, as a button of the device.
</Property>

## Actions

<Property name="pururu.reload" type="action">
  Reads `pururu:` from the YAML again and applies it. Only administrators can call it. It's the same as **Developer tools → YAML → Pururu**.
</Property>
