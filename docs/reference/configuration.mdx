```yaml title="configuration.yaml"
pururu:
  config:
    notify: notify.mobile_app_phone     # where every message goes
    alerts:
      lights:
        groups:
          default: {sala: [teto]}
  events: [state_changed, reading]   # see events
  floors:
    terreo:
      name: Térreo
      level: 0
      icon: mdi:home-floor-0
      aliases: [embaixo]
  areas:
    lavanderia:
      name: Lavanderia
      floor: terreo
      icon: mdi:washing-machine
  devices:
    laundry_washer:
      name: Máquina de lavar
      area: lavanderia
      appliance:
        power: sensor.washer_plug_power
        energy: sensor.washer_plug_energy
        running:
          threshold: 4
          on_delay: {minutes: 1}
          off_delay: {minutes: 2}
        statistics:
          runtime: [today, week, month, year]
          cycles: [today, week, month, year]
        alerts:
          offline:
      phases:
        cycle_from: appliance
        sensor: sensor.washer_plug_power
        defaults:
          stopped: idle
          running: washing
        bands:
          heating: {above: 1000}
          spinning: {above: 50, below: 1000, for: {minutes: 3}}
      alerts:
        long_cycle:
          name: Ciclo longo
          when: appliance_running
          is: "on"
          for: {hours: 3}
          priority: medium
          lights: true
          notify: {message: A máquina está rodando há mais de 3h!, done_message: A máquina terminou.}
      notifications:
        appliance:
          finished:
    pool:
      name: Piscina
      switches:
        pump: {entity: switch.pool_pump, name: Bomba}
      programs:
        clean:
          name: Limpar
          sequence:
            - turn_on: switch_pump
            - delay: {hours: 2}
            - turn_off: switch_pump
          statistics: {runtime: [month], cycles: [month]}
      reactions:
        morning: {name: Manhã, at: "08:00", then: clean, statistics: {triggered: [month]}}
    sala:
      name: Sala
      lights:
        teto: {entity: light.sala_teto, name: Teto}
        abajur: {entity: switch.sonoff_abajur, name: Abajur}
      reactions:
        washer_done: {name: Lavadora terminou, device: laundry_washer, when: appliance_running, from: "on", to: "off", message: A roupa está pronta.}
        night: {name: Noite, at: "22:00"}

automation pururu: !include_dir_merge_list pururu/automations
script pururu: !include_dir_merge_named pururu/scripts

alert2:                          # alerts with notify: see alerts
  alerts: !include_dir_merge_list pururu/alert2
```

## General rules

- `pururu:` has five optional keys: `config`, `floors`, `areas`, `devices` and `events`. Any other key is an error.
- Every **key** you choose, whether of a floor, an area, a device, a phase, a switch, a light, an alert or a program, is a **slug**: lowercase letters, digits and `_`.
- A feature's own `alerts` enables its ready-made alerts, one key each: see the [appliance's](/features/appliance#ready-made-alerts). The device's `alerts` is for alerts you write.
- An alert's `when` names an entity key of another feature of the same device, as it ends the entity ID (`appliance_running`, `switch_pump`). See [alerts](/features/alerts#settings).
- A program's steps name entity keys of other features of the same device the same way, and each one's feature must take the step's action. See [programs](/concepts/programs#steps).
- No two devices give an entity the same ID. Device `pool` with the switch `switch_pump` and device `pool_switch` with the switch `pump` would both have `switch.pururu_pool_switch_switch_pump`, so that's a configuration error. It counts every entity key a feature can create, even one its settings don't: device `pool` with the switch `appliance_energy_total` is refused next to a device `pool_switch` with `appliance`, even without `energy:`, so turning a setting on later never breaks the configuration.
- In one device, a real entity is in one of `switches` and `lights` at most: `switches: switch.sonoff_abajur is already in lights`. Two devices can each use it their own way.
- An unknown key anywhere is a configuration error. When the configuration is invalid, Home Assistant logs why, and a reload **changes nothing**.
- The blocks can be split across [packages](/getting-started/install#packages).

## config

Settings of the whole house, not of a device.

<Property name="notify" type="notify action or list" optional>
  Where every message goes, a reaction's or a ready-made notification's, unless its own `notify` says: `notify.mobile_app_phone`, or a list of them. See [Notifications](/concepts/notifications#where-a-message-goes).
</Property>

---

<Property name="alerts.lights" type="map" optional>
  The alert lights: `groups` of lights that alerts borrow with `lights`, and what a light shows for each priority (`high`, `medium`, `low`) and once its alerts ended (`resolved`). See [Alert lights](/concepts/alert-lights#settings).
</Property>

## floors

A map of **floor ID → floor**. See [Floors and areas](/concepts/floors-and-areas).

<Property name="name" type="string" required>
  The name Home Assistant shows.
</Property>

---

<Property name="level" type="integer" optional>
  The floor's level: `0` for the ground floor, negative below it and positive above it. Leaving it out clears it.
</Property>

---

<Property name="icon" type="icon" optional>
  An icon such as `mdi:home-floor-0`. Leaving it out clears it.
</Property>

---

<Property name="aliases" type="list of strings" optional>
  Other names for the floor, for example for voice assistants. A single string is allowed too.
</Property>

## areas

A map of **area ID → area**. See [Floors and areas](/concepts/floors-and-areas).

<Property name="name" type="string" required>
  The name Home Assistant shows.
</Property>

---

<Property name="floor" type="floor ID" optional>
  The area's floor. It must be a key of `floors:`. Without it, the area is on no floor.
</Property>

---

<Property name="icon" type="icon" optional>
  An icon such as `mdi:stove`. Leaving it out clears it.
</Property>

---

<Property name="aliases" type="list of strings" optional>
  Other names for the area. A single string is allowed too.
</Property>

## events

A list of the classes of [events](/concepts/events) to fire, each once: `state_changed`, `reading`. Leave it out and pururu fires none.

## devices

A map of **device key → device**. See [Devices and features](/concepts/devices-and-features).

<Property name="name" type="string" required>
  The device's name.
</Property>

---

<Property name="area" type="area ID" optional>
  The area the device goes in. It must be a key of `areas:`. See [A device in an area](/concepts/floors-and-areas#a-device-in-an-area).
</Property>

---

<Property name="reactions" type="map" optional>
  A map of **reaction key → reaction**, each one a Home Assistant automation. It isn't a feature. A reaction's `then` names one of the device's `programs`, started when it fires, and its `message` is told to its `notify` or `config.notify`. See [Reactions](/concepts/reactions#settings).
</Property>

---

<Property name="notifications" type="map" optional>
  The ready-made notifications of the device's features to tell, as `feature: notification: settings`, such as `appliance: finished:`. Each one is a Home Assistant automation. It isn't a feature. See [Notifications](/concepts/notifications#ready-made-notifications).
</Property>

---

<Property name="programs" type="map" optional>
  A map of **program key → program**, each one a Home Assistant script. It isn't a feature. See [Programs](/concepts/programs#settings).
</Property>

---

<Property name="<feature>" type="map" required>
  At least one feature, under its own key:

  - [`appliance`](/features/appliance#settings): an appliance on a power-measuring plug.
  - [`door`](/features/door#settings): a door from its contact sensor.
  - [`window`](/features/window): a window from its contact sensor.
  - [`lights`](/features/lights#settings): real lights, or relays that drive a lamp, inside the device.
  - [`phases`](/features/phases#settings): the phase of a cycle.
  - [`modes`](/features/modes#settings): the kind of each cycle.
  - [`switches`](/features/switches#settings): real switches inside the device.
  - [`alerts`](/features/alerts#settings): problems on the device's own entities.
</Property>

## Actions

<Property name="pururu.reload" type="action">
  Reads `pururu:` from the YAML again and applies it. Only administrators can call it. It's the same as **Developer tools → YAML → Pururu**.
</Property>
