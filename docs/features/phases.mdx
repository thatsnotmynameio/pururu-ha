---
title: phases
description: The phase of a cycle, such as heating, spinning or drying, from bands of a sensor's value.
---

`phases` names what the appliance is doing during a cycle. It watches a sensor, usually the plug's power, and compares its value with **bands** you define. The phase is the first band that holds.

```yaml
pururu:
  devices:
    laundry_washer:
      name: Máquina de lavar
      appliance:
        power: sensor.washer_plug_power
        running: {threshold: 4, on_delay: {minutes: 1}, off_delay: {minutes: 2}}
      phases:
        cycle_from: appliance
        sensor: sensor.washer_plug_power
        defaults:
          stopped: idle
          running: washing
        bands:
          heating: {above: 1000}
          spinning: {above: 50, below: 1000, for: {minutes: 3}}
```

## Settings

<Property name="cycle_from" type="feature" required>
  The feature of **this device** whose cycle the phase follows. Today that's `appliance`. See [Features that build on each other](/concepts/devices-and-features#features-that-build-on-each-other).
</Property>

---

<Property name="sensor" type="entity ID" required>
  The sensor whose value picks the phase. It's often the same power sensor as `appliance`'s, but any numeric sensor works, such as a water temperature sensor.
</Property>

---

<Property name="defaults.stopped" type="name" required>
  The phase outside a cycle.
</Property>

---

<Property name="defaults.running" type="name" required>
  The phase during a cycle when no band holds.
</Property>

---

<Property name="bands" type="ordered map of name → band" required>
  At least one band. **Order matters**: when several bands hold, the first one listed wins. Each band has:

  - `above`: the value must be strictly above this.
  - `below`: the value must be strictly below this.
  - `for`: how long the value must stay in the band before the band holds. It's optional and defaults to 0, meaning at once. It's a [time period](/features/appliance#settings), such as `{minutes: 3}`.

  A band needs `above`, `below` or both, and `above` must be lower than `below`.
</Property>

Phase names (the two defaults and every band) are slugs, `lowercase_with_underscores`, and they must all be different.

## How the phase is chosen

- **No cycle** (the cycle's entity is off): the phase is `defaults.stopped`.
- **In a cycle**: the phase is the first band, in the order you listed them, that currently **holds**. When none holds, it's `defaults.running`.
- A band **holds** once the value has stayed inside it for its `for`. If the value leaves the band, its count starts over.
- A reading **without a value** (`unknown`, `unavailable`, or not a number) restarts the count of every band still waiting out its `for`. Bands that already hold keep holding, and the phase doesn't change. This matches how Home Assistant's own `numeric_state` trigger treats `for`.
- Bands are tracked **before** the cycle starts too. If the power is already in a band when the cycle begins, that band's `for` has already been counting.
- While the cycle's entity is `unknown` or `unavailable`, the phase keeps its value.
- After a **restart**, the phase keeps its restored value until the sensor's first reading.

The comparisons are strict. With `heating: {above: 1000}` and `spinning: {above: 50, below: 1000}`, a reading of exactly 1000 W is in neither band.

## Entity

| Entity | What it is |
|---|---|
| `sensor.pururu_<key>_phase_phase` | The current phase: one of your names. Device class `enum`, so its possible states are known to Home Assistant. |

Its attribute **`seen`** lists the bands that held during the current cycle, in the order you listed them. When the cycle ends, `seen` keeps the last cycle's bands until the next cycle starts. Use it to check afterwards whether a wash went through `spinning`.

### State names

These names are translated in the UI (English and Portuguese):

| Name | English | Portuguese |
|---|---|---|
| `idle` | Idle | Parada |
| `washing` | Washing | Lavando |
| `heating` | Heating | Aquecendo |
| `spinning` | Spinning | Centrifugando |
| `rinsing` | Rinsing | Enxaguando |
| `drying` | Drying | Secando |
| `cooling` | Cooling | Esfriando |

Any other name, such as `soaking` or `pre_wash`, is shown as written.

## Needs

`phases` needs a **cycle**. If the cycle's entity (`appliance`'s `running`) can't be created, for example because its ID is taken, `phase` isn't created either. If you rename `running` in the UI, `phase` follows the new ID.
